## 第3回 取締役会 ─ クリック全停止という名の地獄について

> 日付: 2026 年 1 月 11 日（日）
> 議題: 自社カスタム T シャツ生成サービスで、本番公開直後に全クリックが効かなくなった件
> 出席: 議長、CTO、COO、悪魔

その日、僕は半泣きでオフィスのドアを開けました。

前日の土曜日、満を持して公開した自社のカスタム T シャツ生成サービス。ユーザーがブラウザで好きな絵柄を作り、その場で注文できる、半年がかりの小さな自慢の SaaS でした。

ところが、夕方に最初のテスターから連絡が来たのです。「あの、ボタン、押せないんですけど」。

最初は冗談かと思いました。自分のスマホで開いてみると、確かに、押せない。生成ボタンも、注文ボタンも、メニューも、全部。画面は完璧に表示されている。でも、どこを押しても何も起きない。地獄でした。

土曜の夜から日曜の朝にかけて、僕はひとりで原因を探しました。見つかりませんでした。

そして今、長机の向こうには CTO が腕を組んで座っています。隣で COO が無表情にダッシュボードツールを開いている。そして 7 脚目の椅子では、悪魔がリンゴをかじりながら、こっちを見てニヤニヤしていました。

「で、議長、状況は」CTO が口火を切りました。

「クリックが、全部、効きません」

「全部？」

「全部です」

CTO の眉が少しだけ動きました。「それ、根本原因、まだ見えてないでしょ」

「見えてないです」

「動作確認、どこまで戻した？」

「えっと、ローカルでは動くんです。本番だけ、効かない」

COO が顔を上げました。「再現手順は、ありますか」

「あります。本番 URL を開いて、どこでもいいから押す。それだけです」

「いちばん嫌な手順ですね」COO が静かに言いました。「100% 再現で、原因が見えない」

悪魔がリンゴをかじりながら口を開きました。「ね、議長。お前さ、本番にデプロイする前に、本番相当の環境で触った？」

僕は、黙りました。

「ほら来た」悪魔がニヤつきます。「『ローカルでは動くんです』って、半年で何回目？」

CTO が手を挙げて止めました。「悪魔、刺すのは原因が見えてからにしてくれ。今は手を動かす時間だ」

そして CTO は MacBook を開き、こちらに画面を向けました。

ここから 3 時間、地獄のデバッグが始まりました。

最初に CTO がやったのは、ブラウザの開発者ツールを開いて、コンソールを眺めることでした。エラーは、出ていません。ネットワークも正常。HTML は届いている。JavaScript も読み込まれている。なのに、押せない。

「いちばん厄介なやつだ」CTO がつぶやきました。「壊れてるのに、壊れた顔をしてない」

僕は横で、コーヒーを 3 杯おかわりしました。

CTO は次に、SSR で返ってきた HTML と、ブラウザ側で hydrate された後の DOM を、ひとつずつ比べ始めました。Rust で書かれたフロントエンドのフレームワークが、サーバー側で先に HTML を組み立て、それをブラウザに送り、ブラウザ側でイベントハンドラをくっつけ直す ── そういう仕組みです。

「SSR と hydrate のどこかで、ズレてる気がする」CTO が言いました。

「ズレてるって、何がですか」

「分からん。だから探してる」

COO が冷静に「探す手順、書いておいてください」と言いました。「次、誰かが同じバグに当たったとき、3 時間かけたくない」

CTO は無言で頷きました。手は止めません。

1 時間が過ぎ、2 時間が過ぎました。悪魔は途中で「飽きた」と言って椅子の上で逆さまになり、何故か眠そうな顔でリンゴの芯をかじっていました。

僕は、心の中で、よくないことをつぶやいてしまいました。

「これ、もう、Rust、やめません？」

声に出ていました。

CTO は画面から目を離さず、即答しました。

「やめません」

「いや、でも」

「やめません」

「JavaScript なら、もっと早く」

「議長」CTO が初めて顔を上げました。「Rust が原因じゃないです。原因は、まだ分かってないです。分かってないものを犯人にしないでください」

僕は黙りました。悪魔が逆さまのまま「ね、また犯人を作ろうとしたね」と笑いました。

3 時間目に入ったとき、CTO の手がふと止まりました。

エディタの上で、ある関数の上にカーソルを置き、LSP の hover を出した瞬間でした。型情報がポップアップで出ます。CTO はその型を見て、しばらく動かなくなりました。

「ちょっと、ちょっと待って」

「どうしました」

「これ、サーバー側で生成してる ID と、クライアント側で探してる ID、別物だ」

COO が顔を上げました。「と、いいますと」

CTO は画面を指でなぞりました。「SSR でレンダリングするとき、各要素にユニークな ID を振ってる。これがランダムな UUID で生成されてる。サーバー側で 1 回、クライアント側でもう 1 回。同じ関数を呼んでるから同じ値が返ると思いきや、ランダムだから、当然、違う値が返る」

「えっと、それは」

「サーバーが『この要素の ID は A です』と言って HTML を送る。ブラウザ側は受け取った HTML を表示する。ここまではいい。でもブラウザ側で hydrate するとき、もう 1 回 ID を生成しようとする。今度は B が出る。ブラウザは『A の要素にイベントハンドラをつけたい』と思ってるのに、自分が探してるのは B。だから、つかない。だから、押しても、何も、起きない」

地獄の正体でした。

「型は、合ってたんですよ」CTO が小さく笑いました。「両方とも UUID 型。コンパイラは何も文句を言わない。型安全言語だけど、思い込みは型で守れない」

悪魔が、逆さまのまま、こっちを見ました。

「ね、議長、聞いた？ 型安全言語でも、思い込みは型で守れないって」

CTO が珍しく、口の端を上げました。「悪魔、それ、いいこと言うじゃん」

悪魔は珍しく、ちょっと得意げな顔をしました。

修正は、5 分で終わりました。

ランダム生成の ID を、注文データに紐づいた実データの ID に差し替える。サーバーでもクライアントでも、同じデータを見れば、同じ ID が出る。当たり前のことです。当たり前のことが、3 時間、見えませんでした。

僕は本番にデプロイし直し、自分のスマホで開きました。

ボタンを、押しました。

押せました。

長机に突っ伏したくなりました。実際、少し突っ伏しました。

CTO は MacBook を閉じ、コーヒーをひと口飲んでから、僕の方をまっすぐ見ました。

「議長」

「はい」

「ひとつだけ、お願いがあります」

「なんでしょう」

「一時的修正だけは、しないでくれ」

僕は顔を上げました。

「今日のバグ、たとえば『hydrate のとき、エラーを握りつぶす』とか、『ID 不一致を黙って無視する』とか、symptom だけ消す方法は、いくらでもあった。でも、それやってたら、来週、もっと大きい場所で同じバグが出る。今日 3 時間で済んだから、今日のうちに、根本を直す。それだけです」

僕は、深く、頷きました。

何度も、頷きました。

「分かりました」

「Verify Before Done、いつもの口癖ですけど、今日は『Verify Before Deploy』を追加で。本番相当の環境で、ひと通り触ってから出す。手順書、COO に書いてもらいましょう」

COO が即座に「もう書き始めてます」と言いました。

悪魔がリンゴを置きました。

「ね、CTO」

「なんだ」

「お前さ、たまにいいこと言うじゃん」

「お前もな」

二人が、ちょっとだけ笑いました。僕も笑いました。

外はもう、暗くなっていました。

---

### 決定事項
- 本番公開前に、本番相当の環境で全主要動線を手動で触る ── 動作確認の手順書を策定（オーナー: COO、期限: 1 月 18 日まで）
- SSR / hydrate を使う箇所の ID 生成は、ランダム UUID ではなく実データ由来の安定 ID に統一（オーナー: CTO、期限: 即時、当該 SaaS で完了済み）
- 「symptom だけ消す一時的修正」を禁止する原則を、開発ルールに明文（オーナー: 議長、期限: 1 月 25 日まで）
- 持ち越し: 同種の「型が合ってるのに意味が違う」事故の再発防止策、次回までに CTO がたたきを持ってくる

### 議長メモ
*型は守ってくれる。けれど、僕の思い込みまでは守ってくれない。今日のバグは、僕の油断が連れてきた。*

> 半年後の僕は、今でもあの日のことを、ときどき思い出します。「Rust やめる」と叫んだ自分の声と、「やめません」と即答してくれた CTO の声。そして、3 時間後の hover ひとつで全部が見えた瞬間の、長机の静けさ。あの日、僕は CTO のおかげで、もうひとつ大事な癖を覚えました。バグの犯人を、勝手に作らないこと。原因が見えるまでは、誰も悪者にしないこと。Rust も、自分も、悪魔も、です。
