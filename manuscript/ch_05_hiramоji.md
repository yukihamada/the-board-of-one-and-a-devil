## 第5回 取締役会 ─ 平文のまま push してしまった夜について

> 日付: 2026 年 2 月 8 日（日）
> 議題: 開発ブランチに API キーが平文で混入し、公開リポジトリに push 済みであった件
> 出席: 議長、CTO、CFO、悪魔

> あの夜のことを、半年後の僕は、今もたまに思い出します。怖かったのは、流出そのものよりも、自分が「書いてあったルール」を読まずに通り過ぎていた、という事実の方でした。

土曜の夜、十一時を回ったころでした。僕はコーヒーを淹れ直して、なんとなく開発ブランチの履歴を流し読みしていました。週末のうちに、来週分の地ならしをしておこうと思っていたのです。

`git grep` で見覚えのある文字列のかたまりが目に入って、手が止まりました。

外部 API のキーが、設定ファイルではなく、ソースの中に literal で書かれている。しかも `config.rs` に集約するはずの値が、別のファイルで、引用符にくるまれて、静かに居座っている。

息が浅くなりました。コミットログを遡ります。三日前。push 済み。リモートの開発ブランチに、平文のまま、確かに乗っていました。

血の気が引く、というのは、こういう物理的な感覚なんだと、そのとき初めて知りました。指先が冷たくなって、画面の文字がうっすら遠くなる。

僕はその場で鍵をローテーションし、漏洩経路の確認に必要なログを集め、月曜の朝に話すべきことをメモにまとめて、二時過ぎに寝ました。眠れた、とは言えませんでした。

---

日曜の午後四時。長机のいつもの席に、僕は青い顔で座っていました。

「議題は、ひとつです」と僕は切り出しました。「金曜時点の開発ブランチに、外部 API のキーが平文で入っていました。push 済みです。土曜の夜に気づいて、鍵は回しました」

CTO が無言で MacBook を開きました。黒いパーカーの袖をまくる、いつもの動作です。

「履歴、見せて」

僕はターミナルを共有しました。CTO はしばらく黙って、コミットを遡り、ブランチの公開範囲と、push されてから検知するまでの時間差を確認していました。

「露出時間、短い」と、ようやく口を開きました。「公開リポジトリではあるが、対象ブランチの参照頻度から見て、外に拾われた可能性は低い。鍵のローテーションは済んでる。今回はそれで止まる」

CFO が手元のスプレッドシートに目を落として、淡々と言いました。

「数字で言うと、金額被害は計算上、現時点ゼロです。漏洩した鍵に紐づく外部 API は従量課金で、ローテーション前の利用ログにも異常はありません。鍵を回した時点で、金銭的な事故としては、収束しています」

僕は、ほんの少しだけ、肩の力が抜けかけました。

「よかった、と言っていいですか」

「事象としては、よかった、で構いません」と CFO は言いました。「ただし、構造としては、何も終わっていません」

その言葉の意味を僕が受け取りきる前に、悪魔がリンゴをかじりながら、椅子を逆向きに座り直しました。

「ね、議長」と悪魔は、いつもより低い声で言いました。「次、同じことしないために、何する？」

場が、静かになりました。

CTO がコーヒーを置く、その小さな音が、やけに大きく聞こえました。

---

僕は答えに詰まりました。「気をつけます」と言いかけて、その言葉の薄さに自分で気づいて、止めました。

CTO が、画面から目を上げて、口を開きました。

「設定値は `config.rs` 系の一箇所に集約する、っていうルール、書いてあったよね」

「書いて、ありました」と僕は答えました。「先月、CLAUDE.md の方針セクションに、自分で書きました」

「俺もレビューで、見落とした」と CTO は言いました。「ごめん」

ぶっきらぼうな声のままでしたが、最後の二音だけが、いつもより少し低く落ちました。CTO が頭を下げる場面を、僕は半年で初めて見たような気がしました。

「いや」と僕は言いました。「書いた本人が、読まずに通したんだから、レビュー以前の話です」

悪魔が、にやり、と笑いました。

「ね、人間って、書いたルール、読まないでしょ？」

刺さりました。CTO にも、CFO にも、そして何より僕に、まんべんなく刺さりました。

「俺さま、こういうの、たくさん見てきたよ」と悪魔は続けました。「ルール書いたら安心しちゃう人。書いた瞬間に、もう守ったつもりになる人。書いたページ、半年後に開いたことある？ 開いてないでしょ？ 議長、お前のことだよ」

僕は黙りました。先月、自分でキーボードを叩いて書いた、あの方針セクションの行間隔まで、なぜか急に鮮明に思い出されて、けれど内容の方は、半分も覚えていないのでした。

「CTO もね」と悪魔は容赦なく付け足しました。「『動作確認した？』ってお前、毎週言ってるよね。じゃあ『ルール、読み直した？』は、誰が誰に言うの？」

CTO が小さく舌打ちしました。図星のときの、いつもの音です。

CFO が、感情を出さないまま、しかし普段より一拍だけ早く、言葉を継ぎました。

「金額被害がゼロであることと、構造的な脆弱性が残っていることは、別の話です。今回、わたくしは数字としては『無事』と報告しますが、議事録上は『再発防止策が決まるまでは未解決』と記載することを、提案します」

「賛成です」と僕は即答しました。

---

そこから先は、ドライな作業でした。

CTO が、コミット前に平文の鍵らしき文字列を検出する仕組みを、開発機と CI の両方に入れる案を出しました。手元で気づける層と、push される直前で止まる層と、push 後に検知する層、三段で構える。どれかひとつではなく、三つ重ねる。

「ルールは書いた。書いたものを、機械に読ませる」と CTO は言いました。「人間に読ませることを期待した時点で、負け筋だ」

僕は議事録に、その言葉をそのまま書き写しました。

CFO が「導入コストは、ほぼゼロです」と短く付け足し、CTO が「来週の月曜までに、全リポジトリに展開する」と引き取りました。

悪魔が、リンゴの芯を皿に置いて、最後にひとつだけ言いました。

「議長、書いた本人が読まなかった、ってところ、議事録に小さく書くなよ」

僕は、ペンを止めました。

「No Rationalization。失敗を、小さく書かない」と、議事録の余白にメモしました。手が、少しだけ震えていました。

事象としては、鍵を回して終わる話です。金額被害もありませんでした。けれど、ここで「軽微な事象」と書いたら、僕は同じことを、半年後にもう一度やる気がしました。書く文字の大きさが、そのまま、次の僕の警戒心の大きさになる。そんな気がしたのです。

CTO が、画面を閉じながら、ぼそりと言いました。

「ルール書いて満足、はいちばんダサい。書いたら、見られる仕組みまで作って、初めて書いたことになる」

CFO が一度だけ頷きました。悪魔は、もう何も言いませんでした。

---

会議が終わったあと、僕は誰もいない長机に、しばらく座っていました。

ルールを書くだけじゃ足りない、見られる仕組みが要る。

それは、頭では半年前から分かっていたつもりでした。けれど、本当に分かっていたなら、僕は土曜の夜に冷たい指先で履歴を遡ることは、なかったはずです。書いた、と、読まれている、の間には、思っているよりずっと深い谷がある。その谷を埋めるのは、追加の文章ではなく、追加の仕組みなのでした。

謝った CTO の声と、淡々と「構造は終わっていません」と言った CFO の声と、低く「次、同じことしないために」と聞いた悪魔の声を、僕はもう一度、順番に思い出しました。

三人とも、僕を責めませんでした。ただ、僕を、小さくも、扱いませんでした。

---

### 決定事項
- 平文シークレット検出を、コミット前フック・push 前 CI・push 後スキャンの三段で全リポジトリに導入（オーナー: CTO / 期限: 翌週月曜）
- 設定値の集約ルールを CLAUDE.md から、機械的に検証可能なチェックリストへ昇格させる（オーナー: 議長 / 期限: 同上）
- 本件は金額被害ゼロだが、議事録上は「再発防止策の導入完了まで未解決」として扱う（オーナー: CFO / 期限: 導入完了報告まで）
- 持ち越し: 既存リポジトリ全件の履歴スキャン結果レビュー（次回会議の冒頭で報告）

### 議長メモ
*ひとりだと、ルールを書くだけじゃ足りない。見られる仕組みが要る。書いた文字の大きさが、次の僕の警戒心の大きさになる。*

> 半年後の僕は、あの三段の仕組みに、今も毎週助けられています。書いてあるルールに自分が従えない夜が来ることを、あの夜から、僕は前提にして生きるようになりました。
